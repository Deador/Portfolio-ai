# Project Context

## Project

Portfolio

This repository contains the source code, Design System and documentation for a personal Product Design portfolio.

The project is built using an AI-first workflow where AI assists throughout the entire process—from Design System maintenance to frontend implementation and documentation.

The portfolio is intended to demonstrate both design thinking and engineering capability.

---

# Primary Goals

The project has three priorities.

## 1. Strengthen professional positioning

The primary objective is to improve the presentation of the author's experience and skills as a Product Designer.

The portfolio should clearly communicate:

- product thinking
- systems thinking
- Design System expertise
- ability to work with engineers
- AI-assisted workflows
- frontend understanding

The ultimate business goal is career growth and a higher-level Product Design position.

---

## 2. Prepare for BigTech interviews

The portfolio should demonstrate skills expected from Senior Product Designers working on complex digital products.

It should emphasize:

- decision making
- process
- measurable outcomes
- scalable Design Systems
- collaboration with engineering
- production thinking

---

## 3. Demonstrate an AI-first workflow

AI is used as a productivity multiplier.

The project itself should become evidence that modern Product Designers can effectively collaborate with AI during design and development.

---

The first version intentionally has a very small scope.

Pages:

- Home
- Individual Case Study pages

No blog.

No CMS.

No authentication.

No backend.

The focus is quality rather than quantity.

---

# Design Philosophy

The portfolio should communicate:

- clarity
- systems thinking
- attention to detail
- production readiness

Avoid visual noise.

Avoid unnecessary interactions.

Content should remain the primary focus.

---

# Design System

The portfolio is built entirely from a reusable Design System.

The Design System should be:

- reusable
- scalable
- token-based
- documented in Storybook

Every page should be assembled from reusable components rather than custom layouts.

---

# Content

Content is stored locally as structured JSON files.

The application parses JSON and renders reusable sections.

No CMS is used.

This keeps the project lightweight while remaining easy to maintain.
